# Testing strategy

| Layer | Tool | Where | Calls AWS? |
|---|---|---|---|
| Pure logic (schemas, diff, citations, Excel map) | pytest | `backend/tests/` | No |
| AWS-facing code (registry, handlers, Textract parsing) | pytest + `moto` or `botocore.stub.Stubber`, saved JSON responses | `backend/tests/` | No |
| Templates | `cfn-lint`, plus pytest assertions on the parsed YAML (encryption, public access, IAM scope) | `infra/tests/` | No |
| Integration | pytest, `@pytest.mark.aws`, dev account | `tests/integration/` | Yes, synthetic fixtures only |
| Extraction quality | Eval harness over synthetic fixtures with expected extractions | `evals/` | Yes (Bedrock) |

## Rules

- Each FR a task covers gets at least one test that names it, e.g.
  `def test_fr12_flags_gap_between_periods()`.
- Model output tests cover: valid parse, schema failure, `max_tokens`, `refusal`, "not stated",
  and a citation excerpt that is not on the cited page.
- Comparison tests include a renumbered or reworded control pair and a period gap.
- Prior-report lookup tests mix two vendors, two systems, SOC 1 and SOC 2 (D-24).
- **Eval gate:** any change to the prompt version or model ID runs `evals/` and the PR shows
  the scores before and after. Targets are proposed in `requirements.md` §7 and open (O-7).
- Fixtures are generated by `tests/fixtures/generate.py`. Never real reports (O-4).
- While iterating, run one test file; run `make check` before the PR.
